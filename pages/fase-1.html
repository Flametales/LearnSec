1.1

Mentale Modellen —
Voorbij CIA.

WEEK 1

De CIA triad is een startpunt, geen eindpunt. Leer de frameworks die security professionals echt gebruiken om dreigingen te modelleren en risico's te begrijpen.

01

Threat Modeling Frameworks

De CIA triad (Confidentiality, Integrity, Availability) is overal, maar het mist nuance. De Parkerian Hexad voegt Possession, Authenticity en Utility toe — cruciaal voor moderne systemen. STRIDE (Spoofing, Tampering, Repudiation, Information Disclosure, Denial of Service, Elevation of Privilege) geeft je een gestructureerde manier om dreigingen per component te classificeren.

Diep Begrip: Waarom CIA-triad niet genoeg is

De CIA-triad (Confidentiality, Integrity, Availability) is een handig ezelsbruggetje, maar het mist cruciale dimensies. De Parkerian Hexad voegt Possession (fysieke controle over data), Authenticity (bewijs van oorsprong), en Utility (bruikbaarheid) toe.

Voorbeeld: een versleutelde backup waarvan je de sleutel kwijt bent heeft perfecte confidentiality en integrity, maar nul utility. Supply chain aanvallen (SolarWinds) schenden authenticity zonder traditionele CIA te raken — de software WAS integer, maar niet authentiek.

Diepere Frameworks

  • PASTA — Process for Attack Simulation and Threat Analysis: risico-gedreven, business-context eerst
  • OCTAVE — Operationally Critical Threat, Asset, and Vulnerability Evaluation: asset-centric, organisatie-breed
  • LINDDUN — Privacy threat modeling: Linkability, Identifiability, Non-repudiation, Detectability, Disclosure, Unawareness, Non-compliance
  • Attack Trees (Schneier) — Hiërarchische decompositie van aanvalspaden: root node = doel, bladeren = atomaire acties
  • Assume Breach — Het mentale model dat moderne defense definieert: ga ervan uit dat de aanvaller al binnen is. Ontwerp vanuit die realiteit.

OEFENING 1.1.1 MEDIUM
Attack Tree: Web App met Betalingen
Bouw een attack tree voor een webapplicatie met payment processing. Root node: "Steal Customer Payment Data". Decomponeer in minimaal 3 niveaus diep. Identificeer leaf nodes en markeer de meest waarschijnlijke en goedkoopste aanvalspaden.
Toon antwoord

Root: "Steal payment data". Branches: 1) SQL injection op checkout form → extract DB, 2) XSS op betaalpagina → capture form input, 3) Compromise payment processor API key → direct API access, 4) Social engineer developer → source code access → hardcoded credentials. Elke branch heeft sub-branches met difficulty/cost ratings.

OEFENING 1.1.2 MEDIUM
STRIDE op Je Thuisnetwerk
Pas STRIDE toe op je eigen thuisnetwerk. Teken eerst een diagram van alle componenten (router, apparaten, services). Documenteer voor elke STRIDE-categorie minimaal één concrete dreiging en een mitigatie.
Toon antwoord

Spoofing: ARP spoofing door kwaadaardig apparaat, DNS spoofing door compromised router. Tampering: MITM op onversleuteld verkeer, firmware manipulatie van IoT devices. Repudiation: Geen logging op router = geen bewijs van aanval. Information Disclosure: Unencrypted WiFi traffic, UPnP exposing services. DoS: Router resource exhaustion, WiFi deauth. Elevation: Default credentials op IoT, exploiting router admin panel.

OEFENING 1.1.3 EASY
CIA vs Parkerian Hexad Vergelijking

Toon antwoord

Cloud storage voorbeeld: CIA zegt versleuteling = confidentiality OK. Parkerian Hexad vraagt ook: is de data authentiek (niet gemanipuleerd door cloud provider)? Heb je possession (wat als provider failliet gaat)? Is het utility (kun je het nog lezen over 10 jaar)?

1.2

Cryptografie —
Echt begrijpen.

WEEK 1-2

Cryptografie is niet "gebruik AES en je bent veilig". Begrijp de modes, de wiskunde, de aanvallen, en waarom forward secrecy bestaat. Dit is de taal van security.

02

Van Primitives tot Protocollen

Diep Begrip: Waarom ECB mode een meme is en GCM nonce-reuse catastrofaal

ECB versleutelt elk blok onafhankelijk met dezelfde key. Identieke plaintext-blokken → identieke ciphertext-blokken. Het beroemde “ECB penguin” beeld toont dit visueel.

GCM combineert CTR-mode encryptie met GHASH authenticatie. Maar als je een nonce hergebruikt: de XOR van twee ciphertexts = XOR van twee plaintexts (CTR keystream cancelt), EN de authenticatie key lekt volledig via de GHASH polynoom. Eén nonce hergebruik = game over.

Dit is waarom AES-GCM-SIV bestaat als nonce-misuse-resistant alternatief.

Symmetrische Cryptografie

  • AES modes — ECB (nooit gebruiken), CBC (IV nodig, padding oracle), CTR (stream-achtig), GCM (authenticated encryption — de standaard)
  • Block vs Stream ciphers — AES = block, ChaCha20 = stream. Wanneer welke? Performance, hardware support, nonce-reuse gevolgen

Hashing & Key Derivation

  • KDFs vs Hashes vs MACs — SHA-256 (hash), HMAC-SHA256 (MAC), PBKDF2/bcrypt/scrypt/Argon2 (KDF). Elk heeft een ander doel. Verwar ze niet.
  • Password hashing — Argon2id is de huidige standaard. bcrypt als fallback. Nooit SHA-256 voor wachtwoorden.

Asymmetrische Cryptografie & Key Exchange

  • Diffie-Hellman — Het elegante key exchange protocol. Begrijp de discrete logarithm problem en waarom het werkt.
  • ECC (Elliptic Curve Cryptography) — Kleiner keys, zelfde veiligheid. Curve25519 is de gouden standaard.
  • Forward Secrecy — Ephemeral keys zorgen dat compromised long-term keys geen oude sessies onthullen.

TLS & Quantum

  • TLS 1.3 — 1-RTT handshake, verplicht forward secrecy, geen RSA key exchange meer, AEAD-only cipher suites
  • Post-quantum — CRYSTALS-Kyber (key exchange), CRYSTALS-Dilithium (signatures). Hybride aanpak: klassiek + PQ samen

OEFENING 1.2.3 EASY
XOR Encryption in Python
Implementeer XOR encryption en decryption in Python. Schrijf functies voor single-byte XOR, multi-byte XOR, en demonstreer waarom XOR met een herhalende korte key kwetsbaar is voor frequentie-analyse.
Toon antwoord

def xor_encrypt(plaintext, key): return bytes([p ^ key[i % len(key)] for i, p in enumerate(plaintext)])

Om te kraken: als je de key-lengte weet, splits de ciphertext in kolommen en kraak elke kolom als single-byte XOR via frequency analysis (meest voorkomende byte = ‘e’ of spatie XOR key-byte).

OEFENING 1.2.4 MEDIUM
TLS 1.3 Handshake Capture
Capture een TLS 1.3 handshake met Wireshark. Identificeer elke message: ClientHello, ServerHello, EncryptedExtensions, Certificate, CertificateVerify, Finished. Noteer de cipher suite en key exchange methode.
Toon antwoord

ClientHello (supported versions, cipher suites, key_share met ECDH public key) → ServerHello (gekozen cipher suite, key_share met server ECDH public key) → Server Certificate + CertificateVerify + Finished (allemaal versleuteld met handshake keys) → Client Finished.

Verschil met TLS 1.2: geen RSA key exchange (alleen DHE/ECDHE), 1-RTT in plaats van 2-RTT, alle data na ServerHello is versleuteld.

1.3

OS Security op
Aanvaller-Niveau.

WEEK 2-3

Begrijp hoe Windows en Linux intern werken vanuit het perspectief van een aanvaller. Niet alleen "wat is NTLM" maar "hoe extract ik NTLM hashes en wat kan ik ermee".

03

Windows & Linux Internals voor Hackers

Diep Begrip: Waarom LSASS het doelwit is

LSASS (Local Security Authority Subsystem Service) beheert authenticatie op Windows. Het laadt authentication packages (msv1_0.dll voor NTLM, kerberos.dll voor Kerberos, wdigest.dll voor Digest). Wanneer een gebruiker inlogt, slaat LSASS credentials op in geheugen voor SSO.

Mimikatz leest deze credentials rechtstreeks uit LSASS’s proces-geheugen. Dit is waarom Credential Guard (virtualization-based security) LSASS isoleert in een aparte virtuele omgeving waar zelfs kernel-level code niet bij kan.

Windows Security Internals

  • LSASS — Local Security Authority Subsystem Service: het proces dat credentials beheert. Mimikatz target dit. Begrijp de authenticatieflow.
  • NTLM & Kerberos — NTLM: challenge-response, pass-the-hash kwetsbaar. Kerberos: ticket-based, maar golden ticket en silver ticket aanvallen bestaan.
  • SIDs & ACLs — Security Identifiers en Access Control Lists: hoe Windows autorisatie werkt op object-niveau.
  • Event Logs — Windows Event Log: 4624 (logon success), 4625 (logon failure), 4672 (special privileges), 4688 (process creation). Sysmon voor diepere visibility.
  • Registry — De Windows registry als aanvalsoppervlak: persistence, configuratie, credential storage.

Linux Security Internals

  • /etc/shadow — Password hashes opgeslagen met salt. Format: $algorithm$salt$hash. John the Ripper en Hashcat zijn je tools.
  • PAM (Pluggable Authentication Modules) — Modulaire authenticatie stack. Configureerbaar per service: SSH, sudo, login.
  • SELinux & AppArmor — Mandatory Access Control frameworks. SELinux: label-based, AppArmor: path-based. Beide beperken wat processen mogen.
  • Linux Capabilities — Fijnmazige privileges in plaats van alles-of-niets root. CAP_NET_RAW, CAP_SYS_ADMIN, etc. SUID binaries met extra capabilities = privilege escalation vectoren.
  • eBPF — Extended Berkeley Packet Filter: kernel-level observability zonder kernel modules. Gebruikt voor security monitoring, networking, en tracing.

Oefeningen

OEFENING 1.3.1 MEDIUM
LSASS Authenticatie Flow Diagram
Documenteer de volledige LSASS authenticatieflow met een diagram. Van gebruiker-invoer tot token-creatie. Markeer waar Mimikatz, pass-the-hash, en pass-the-ticket aanvallen ingrijpen.
Toon antwoord

User login → winlogon.exe → LSASS → authentication package (NTLM: msv1_0.dll hashes het wachtwoord en vergelijkt met SAM/AD, Kerberos: kerberos.dll vraagt TGT bij KDC). Bij succes: LSASS maakt een logon session en access token. Credentials blijven in LSASS geheugen voor SSO.

WDigest (als ingeschakeld) slaat plaintext wachtwoord op. Protective measures: Credential Guard, RunAsPPL, disabling WDigest.

OEFENING 1.3.2 MEDIUM
PAM Configuratie voor SSH 2FA
Stel PAM configuratie in voor SSH two-factor authenticatie op een Linux VM. Gebruik Google Authenticator PAM module of een vergelijkbaar TOTP-systeem. Test dat je zowel wachtwoord als OTP nodig hebt.
Toon antwoord

Bewerk /etc/pam.d/sshd, voeg toe: auth required pam_google_authenticator.so. Installeer libpam-google-authenticator, run google-authenticator per user.

PAM stack werkt als pipeline: auth (verificatie), account (autorisatie), password (wachtwoord wijzigen), session (setup/teardown). ‘required’ vs ‘requisite’: required gaat door na falen (verbergt welke stap faalde), requisite stopt meteen.

OEFENING 1.3.3 MEDIUM
Sysmon Event Monitoring
Installeer Sysmon op een Windows machine (of VM). Configureer het met een goede config (bijv. SwiftOnSecurity). Genereer en capture Event IDs 4624 (logon success), 4625 (logon failure), en 4672 (special privilege logon). Analyseer de events.
Toon antwoord

4624 = succesvolle logon (type 2=interactive, 3=network, 10=remote interactive). 4625 = gefaalde logon. 4672 = special privileges assigned (admin logon). Sysmon Event 1 = Process Creation (met command line). Event 3 = Network Connection. Event 10 = Process Access (detecteert LSASS dumping).

Gebruik: wevtutil qe Security /q:"*[System[EventID=4624]]" /c:10

OEFENING 1.3.4 EASY
Linux Capabilities Enumeratie
Enumereer Linux capabilities op alle SUID binaries op je systeem. Gebruik getcap en find. Identificeer welke binaries extra capabilities hebben en of deze misbruikt kunnen worden voor privilege escalation. Raadpleeg GTFOBins.
Toon antwoord

find / -perm -u=s -type f 2>/dev/null vindt alle SUID binaries. getcap -r / 2>/dev/null vindt binaries met capabilities.

Vergelijk: /usr/bin/ping met SUID heeft ALLE root privileges tijdens executie. Met cap_net_raw+ep heeft het alleen raw socket access. GTFOBins toont welke SUID binaries misbruikt kunnen worden voor privilege escalation.

1.4

Web op
Protocol-Niveau.

WEEK 3

De meeste "web hackers" begrijpen HTTP niet echt. Leer het protocol op RFC-niveau, begrijp CORS en CSP volledig, en snap waarom JWT-implementaties zo vaak fout gaan.

04

HTTP, Security Headers & Tokens

Diep Begrip: Same-Origin Policy vs Same-Site

Dit zijn VERSCHILLENDE concepten die vaak verward worden. Origin = scheme + host + port (https://example.com:443). Site = registrable domain (example.com).

Twee URLs zijn same-origin alleen als ALLE drie componenten matchen. Ze zijn same-site als de registrable domain matcht (sub.example.com en example.com zijn same-site maar cross-origin).

SameSite cookies gebruiken de ‘site’ definitie, niet ‘origin’. Dit verschil is cruciaal voor CSRF-preventie: SameSite=Lax blokkeert cross-site requests maar niet cross-origin requests van subdomains.

HTTP Protocol Familie

  • HTTP/1.1 (RFC 9110/9112) — Text-based, head-of-line blocking, connection reuse via keep-alive. Ken de methods, status codes, en headers op je duim.
  • HTTP/2 — Binary framing, multiplexing, header compression (HPACK), server push. Één TCP-connectie, meerdere streams.
  • HTTP/3 + QUIC — UDP-based, geïntegreerde TLS 1.3, geen head-of-line blocking op transport-niveau. De toekomst van het web.

Browser Security Model

  • Cookies & SameSite — SameSite=Strict, Lax, None. Begrijp het verschil en waarom Lax nu de default is. Secure, HttpOnly, en __Host- prefix.
  • SOP vs Same-Site — Same-Origin Policy (scheme + host + port) vs Same-Site (eTLD+1). Twee verschillende concepten die vaak verward worden.
  • CORS — Cross-Origin Resource Sharing: preflight requests, Access-Control-Allow-Origin, credentialed requests. Misconfiguratie = data exfiltration.
  • CSP — Content Security Policy: script-src, style-src, nonces, hashes. De krachtigste XSS-mitigatie als je het goed configureert.

Tokens & Real-time

  • JWT (JSON Web Tokens) — Header.Payload.Signature. Veelvoorkomende aanvallen: alg:none, key confusion (RS256 → HS256), weak secrets.
  • WebSockets — Full-duplex communicatie. Upgrade van HTTP. Andere security considerations: geen SOP, CSWSH aanvallen.

Oefeningen

OEFENING 1.4.1 EASY
Handmatige HTTP Requests met curl
Gebruik curl om handmatig HTTP/1.1 requests te craftten met verschillende methods (GET, POST, PUT, DELETE, OPTIONS). Stuur custom headers, cookies, en request bodies. Analyseer de response headers nauwkeurig.
Toon antwoord

curl -v -X POST -H 'Content-Type: application/json' -d '{"user":"test"}' http://target/api

De -v flag toont de volledige HTTP request/response headers. Probeer ook: HEAD (metadata only), OPTIONS (CORS preflight simulatie), PUT vs POST semantiek.

OEFENING 1.4.2 MEDIUM
Strict CSP met Nonces
Zet een testpagina op en configureer een strikt Content Security Policy met nonces. Gebruik script-src 'nonce-...' en verifieer dat inline scripts zonder het juiste nonce geblokkeerd worden. Test met de browser DevTools.
Toon antwoord

Content-Security-Policy: default-src 'none'; script-src 'nonce-abc123'; style-src 'self'; img-src 'self' data:; connect-src 'self'

Elke <script> tag heeft nonce='abc123' nodig. De nonce moet per-request random gegenereerd worden. strict-dynamic laat nonced scripts andere scripts laden.

OEFENING 1.4.3 MEDIUM
JWT Token Analyse & alg:none
Decode een JWT token handmatig (Base64URL decode header en payload). Identificeer de claims en het algoritme. Test voor de alg:none kwetsbaarheid: verwijder de signature en verander het algoritme naar "none". Gebruik jwt.io als hulpmiddel.
Toon antwoord

echo 'eyJhbGciOiJIUzI1NiJ9.eyJ1c2VyIjoiYWRtaW4ifQ.xxx' | cut -d. -f2 | base64 -d

Header bevat alg (algoritme) en typ. alg:none attack: verander header naar {"alg":"none"}, verwijder de signature. RS256→HS256 confusion: als server RS256 publieke key als HMAC secret accepteert.

OEFENING 1.4.4 MEDIUM
CORS Headers & Preflight
Configureer CORS headers op een simpele webserver (Node.js, Python, of nginx). Test preflight requests met custom headers en methods. Verifieer dat de browser OPTIONS requests stuurt en analyseer de Access-Control-* response headers.
Toon antwoord

Access-Control-Allow-Origin moet specifiek zijn, niet * met credentials. Preflight: browser stuurt OPTIONS met Origin en Access-Control-Request-Method. Server antwoordt met allowed origins/methods/headers.

Veelgemaakte fout: dynamisch Origin header reflecteren zonder whitelist = universele CORS bypass.

Home Lab —
Bouw Het Goed.

WEEK 3-4

Je lab is je veilige speeltuin voor de rest van je leerpad. Investeer nu tijd in een goede setup en je plukt er maanden de vruchten van. Geïsoleerd, gedocumenteerd, en monitored.

05

Professionele Lab Omgeving

Diep Begrip: Waarom je lab ge-isoleerd MOET zijn

Een lab met kwetsbare machines op je thuisnetwerk is zelf een kwetsbaarheid. Host-only netwerken zorgen dat lab-verkeer nooit je echte netwerk bereikt. Maar denk ook aan: DNS leakage (kwetsbare VM’s die DNS queries naar internet sturen), clipboard sharing (credentials kopiëren tussen host en VM), shared folders (malware die escaped naar je host).

Proxmox als type-1 hypervisor is veiliger dan VirtualBox (type-2) omdat er geen host OS is dat gecompromitteerd kan worden.

Virtualisatie Platform

  • Proxmox VE — Type-1 hypervisor, gratis, enterprise-grade. Ideaal als je dedicated hardware hebt. KVM + LXC containers.
  • VirtualBox — Type-2 hypervisor, cross-platform. Goed genoeg om te starten. Internal networks voor isolatie.
  • Geïsoleerde netwerken — Nooit je lab aan je productie-netwerk hangen. Host-only of internal networks. NAT alleen voor updates.

Aanvals-machines

  • Kali Linux — De standaard aanvals-distributie. Pre-geïnstalleerde tools: Nmap, Burp, Metasploit, John, Hashcat, etc.
  • Parrot OS — Lichtere alternative voor Kali. Goede privacy-tools ingebouwd.
  • Ubuntu Server — Je basis Linux voor custom tooling en scripting.

Kwetsbare Doelwitten

  • Metasploitable 2/3 — Opzettelijk kwetsbare Linux VM. Perfecte eerste doelwit voor exploitatie-oefeningen.
  • DVWA — Damn Vulnerable Web Application. Web security basics: SQLi, XSS, CSRF, file inclusion, command injection.
  • OWASP Juice Shop — Moderne kwetsbare web app. Angular frontend, REST API, scoreboard met challenges.

Active Directory Lab

  • GOAD (Game of Active Directory) — Volledig geconfigureerde AD lab met misconfigurations, trusts, en aanvalspaden. Meerdere domains en forests.

Monitoring

  • Wazuh — Open-source SIEM + XDR. Agents op al je lab machines. Zie wat je aanvallen genereren vanuit defender-perspectief.
Lab Tip Documenteer je lab setup vanaf dag één. IP-adressen, credentials, netwerk-diagrammen, geinstalleerde tools. Je toekomstige zelf zal je dankbaar zijn. Gebruik een wiki (bijv. Obsidian of Notion) specifiek voor je lab.

OEFENING 1.5.1 MEDIUM
Virtualisatie & Netwerk Isolatie
Installeer Proxmox of VirtualBox en maak geïsoleerde netwerksegmenten. Minimaal: een "attack" netwerk, een "target" netwerk, en een "monitoring" netwerk. Documenteer je netwerk-topologie met een diagram.
Toon antwoord

Maak drie netwerken: ‘attacker’ (10.10.10.0/24), ‘target’ (10.10.20.0/24), ‘ad-internal’ (10.10.30.0/24). In VirtualBox: Host-Only Adapter per netwerk.

De aanvaller-VM krijgt interfaces op alle netwerken. Target en AD netwerken zijn volledig geïsoleerd van internet en van elkaar (behalve via de aanvaller).

OEFENING 1.5.2 EASY
Basis Lab Deployment
Deploy Kali Linux, Metasploitable 2, en DVWA in je lab. Verifieer dat Kali de doelwitten kan bereiken maar dat het lab geïsoleerd is van je thuisnetwerk. Doe een eerste Nmap scan van Metasploitable.
Toon antwoord

Kali: standaard credentials kali/kali. Metasploitable 2: msfadmin/msfadmin, poorten 21, 22, 23, 25, 80, 111, 139, 445, 512-514, 1099, 1524, 2049, 2121, 3306, 5432, 5900, 6000, 6667, 8009, 8180.

DVWA: admin/password, stel Security Level in op ‘Low’ om te beginnen, werk naar ‘High’.

OEFENING 1.5.3 HARD
Active Directory Forest
Zet een basis Active Directory forest op: 1 Domain Controller (Windows Server) + 2 werkstations (Windows 10/11). Maak users, groepen, en een simpele GPO. Dit is je speeltuin voor AD-aanvallen in latere fases.
Toon antwoord

Windows Server 2019 als DC: Install-WindowsFeature AD-Domain-Services; Install-ADDSForest -DomainName lab.local. Voeg 2 Windows 10 machines toe aan het domein.

Maak 10+ gebruikers met variërende wachtwoord-sterkte (sommige Kerberoastable). Install ADCS met vulnerable templates voor ESC1.

OEFENING 1.5.4 MEDIUM
Wazuh SIEM Deployment
Installeer Wazuh (server + dashboard) en deploy agents op al je lab machines. Verifieer dat je logs ontvangt van elke machine. Genereer een test-alert (bijv. failed SSH login) en bekijk het in het Wazuh dashboard.
Toon antwoord

Wazuh server op een aparte Linux VM. Install agents op alle Windows en Linux machines. Verifieer: tail -f /var/ossec/logs/alerts/alerts.json.

Je zou login events, file integrity changes, en vulnerability scan resultaten moeten zien.

Ethische Grenzen

Alles wat je in deze fase leert is dual-use kennis. Dezelfde technieken die security professionals gebruiken om systemen te beschermen, kunnen ook misbruikt worden om ze aan te vallen. Het verschil zit in één woord: autorisatie.

  • Werk uitsluitend in je eigen lab-omgeving of op systemen waarvoor je expliciete schriftelijke toestemming hebt.
  • Bug bounty programma's zijn een legale manier om je skills te oefenen op echte systemen — maar lees altijd de scope en regels.
  • Het ongeautoriseerd testen van andermans systemen is strafbaar, ook als je "alleen maar keek" of "geen schade aanrichtte".
  • In Nederland valt dit onder de Wet Computercriminaliteit. Straffen variëren van boetes tot gevangenisstraffen.
  • Responsible disclosure is een ethische verplichting: als je per ongeluk een kwetsbaarheid vindt, meld het via het NCSC of het bedrijf zelf.
