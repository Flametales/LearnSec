2.1

Reconnaissance & OSINT

2-3 WEKEN

Elke aanval begint met informatie. Hoe meer je weet over je doelwit vóór je eerste exploit, hoe effectiever je bent. Leer passieve en actieve verkenning tot op mastery-niveau.

Diep Begrip: Passieve vs. Actieve Reconnaissance

Het verschil tussen passieve en actieve recon is juridisch, niet technisch — Passieve recon (CT logs, Shodan, Wayback Machine) raakt het doelsysteem nooit direct. Je leest alleen publiek beschikbare informatie. Actieve recon (nmap scans, directory bruteforcing) stuurt verkeer naar het doelsysteem en is detecteerbaar. In Nederland kan actieve recon zonder toestemming al onder Art. 138ab vallen. Het grijze gebied: is een DNS query passief of actief? Technisch gezien raakt het de authoritative nameserver van het doel. In de praktijk wordt het als passief beschouwd, maar wees bewust van de grens.

P

Passieve Reconnaissance

Informatie verzamelen zonder het doelwit te raken. Geen enkel pakket naar de target — puur open bronnen en third-party data.

Kernconcepten

  • Certificate Transparency — gebruik crt.sh om alle uitgegeven certificaten (en dus subdomeinen) van een domein te vinden
  • Shodan & Censys — internet-brede scanners die services, banners, en kwetsbaarheden indexeren. Leer geavanceerde queries schrijven
  • GitHub Dorking — zoek naar gelekte credentials, API keys, en interne documentatie in publieke repositories
  • TruffleHog — automatisch scannen van git-geschiedenis op secrets en high-entropy strings
  • Wayback Machine — historische snapshots van websites onthullen vaak verwijderde pagina's, oude endpoints, en vergeten configuraties
  • DNS History — SecurityTrails, DNSdumpster — wie hoste wat, wanneer? Oude IP's onthullen infrastructuur

A

Actieve Reconnaissance

Nu raak je het doelwit. Port scanning, service enumeration, subdomain bruteforcing. Precisie en snelheid zijn essentieel.

Kernconcepten

  • Nmap Mastery — SYN scan, version detection, scripting engine (NSE), timing templates, output formats. Ken elke flag
  • Masscan — internet-snelheid scanning. Wanneer nmap te langzaam is voor grote ranges
  • Subdomain Enumeration — amass, subfinder — combineer meerdere bronnen voor maximale dekking
  • HTTP Probing — httpx voor het valideren van live hosts, gowitness voor visuele screenshots van ontdekte webservices

Oefeningen

OEFENING 2.1.1 EASY
crt.sh Subdomain Enumeratie
Gebruik crt.sh om alle subdomeinen van een target domein te enumereren. Gebruik je eigen domein of een domein binnen een bug bounty scope. Documenteer elk uniek subdomein en categoriseer ze (productie, staging, dev, intern).
Toon antwoord

curl -s 'https://crt.sh/?q=%25.example.com&output=json' | jq '.[].name_value' | sort -u. CT logs bevatten elk certificaat dat door een trusted CA is uitgegeven. Wildcard certs tonen de scope, individuele certs tonen specifieke subdomains. Combineer met subfinder -d example.com en amass enum -d example.com voor completere resultaten.

OEFENING 2.1.2 MEDIUM
Custom Shodan Query
Schrijf een geavanceerde Shodan query om blootgestelde databases (MongoDB, Elasticsearch, Redis) in een specifiek land te vinden. Experimenteer met filters zoals country:, port:, product:, en vuln:.
Toon antwoord

country:NL port:27017 -authentication voor onbeschermde MongoDB's in Nederland. Andere nuttige queries: has_screenshot:true country:NL (RDP/VNC), ssl.cert.subject.CN:*.company.com (alle services van een bedrijf), http.title:Dashboard -login (onbeschermde admin panels).

OEFENING 2.1.3 MEDIUM
Subdomain Merge Pipeline
Draai amass + subfinder + crt.sh tegen hetzelfde doelwit. Merge alle resultaten in één bestand, elimineer duplicaten, en sorteer. Gebruik httpx om te valideren welke subdomeinen live zijn. Documenteer het verschil in dekking tussen de tools.
Toon antwoord

subfinder -d target.com -o subs1.txt && amass enum -d target.com -o subs2.txt && curl -s 'https://crt.sh/?q=%25.target.com&output=json' | jq -r '.[].name_value' > subs3.txt && cat subs1.txt subs2.txt subs3.txt | sort -u > all_subs.txt. Gebruik httpx om live hosts te identificeren: cat all_subs.txt | httpx -title -status-code -tech-detect.

OEFENING 2.1.4 MEDIUM
Full Nmap Lab Scan
Voer een volledige nmap scan uit op je lab-netwerk. Gebruik -sV voor versiedetectie, -sC voor default scripts, en -O voor OS-detectie. Documenteer alle gevonden services, versienummers, en potentiële kwetsbaarheden.
Toon antwoord

nmap -sV -sC -O -oA lab_scan 10.10.10.0/24. -sV: service version detection, -sC: default scripts, -O: OS detection. Voor stealth: -sS (SYN scan, half-open). Documenteer: IP, open poorten, services+versies, OS. Dit is je aanvalsoppervlak-inventaris.

Checklist

  • Ik kan crt.sh, Shodan, en Censys effectief gebruiken voor passieve recon
  • Ik begrijp GitHub dorking en kan TruffleHog draaien op repositories
  • Ik kan Wayback Machine en DNS history gebruiken om verborgen infrastructuur te vinden
  • Ik beheers nmap volledig: scan types, NSE scripts, timing, output
  • Ik kan masscan gebruiken voor snelle, brede scans
  • Ik kan subdomeinen enumereren met amass en subfinder en resultaten mergen
  • Ik kan httpx en gowitness gebruiken voor HTTP probing en visuele recon
  • Ik kan een complete recon-workflow uitvoeren van passief naar actief
2.2

Web Application Security

10-14 WEKEN — GROOTSTE MODULE

Dit is de grootste module van het hele curriculum. Web applicaties zijn het primaire aanvalsoppervlak van vrijwel elke organisatie. Leer elke kwetsbaarheidsklasse tot op diep niveau.

Diep Begrip: Waarom PortSwigger Academy Onvervangbaar Is

Er zijn honderden web security cursussen, maar PortSwigger's labs zijn geschreven door dezelfde mensen die Burp Suite bouwen en die de originele onderzoekspapers publiceren (James Kettle's HTTP Request Smuggling, Web Cache Poisoning, etc.). De labs zijn niet theoretisch — het zijn echte kwetsbaarheden in echte (sandboxed) applicaties. Het verschil met CTFs: PSA labs zijn methodisch opgebouwd van beginner tot expert, elke lab bouwt op de vorige. 100-200 uur klinkt veel, maar het is de meest efficiënte investering in web security die je kunt maken.

Verplicht Platform PortSwigger Web Security Academy is DE verplichte resource voor deze module. Doe elk lab. Budget 100-200 uur alleen hiervoor. Dit is niet optioneel — het is de industriestandaard voor web security training.
INJ

Injection Attacks

De moeder van alle kwetsbaarheden. Als gebruikersinput ongevalideerd in een interpreter terechtkomt, heb je een injectie.

SQL Injection (Alle Types)

  • Classic SQLi — UNION-based, error-based, inline queries
  • Blind SQLi — boolean-based en time-based. Wanneer je geen output ziet maar het gedrag observeert
  • Second-order SQLi — input wordt opgeslagen en pas later geïnjecteerd in een query
  • Out-of-band SQLi — DNS en HTTP exfiltratie wanneer andere kanalen geblokkeerd zijn

Command Injection

  • OS command injection via ;, |, $(), backticks
  • Blind command injection — time delays, out-of-band (DNS, HTTP)

Server-Side Template Injection (SSTI)

  • Template engine fingerprinting (Jinja2, Twig, Freemarker, Velocity)
  • Van SSTI naar RCE — sandbox escapes en gadget chains

Server-Side Request Forgery (SSRF)

  • Basic SSRF naar interne services
  • Blind SSRF met out-of-band technieken
  • SSRF naar cloud metadata endpoints (169.254.169.254)
  • Filter bypass technieken: URL parsing, DNS rebinding, IPv6
XSS

Cross-Site Scripting (XSS)

JavaScript injectie in de browser van het slachtoffer. Nog steeds een van de meest voorkomende kwetsbaarheden op het web.

XSS Varianten

  • Reflected XSS — payload in de URL, direct gereflecteerd in de response
  • Stored XSS — payload opgeslagen in de database, uitgevoerd bij elke page load
  • DOM-based XSS — kwetsbaarheid zit puur in client-side JavaScript, nooit naar de server
  • Mutation XSS (mXSS) — misbruik van browser HTML parsing quirks om sanitizers te omzeilen
  • CSP Bypass — Content Security Policy omzeilen via unsafe-inline, base-uri, JSONP endpoints, Angular sandbox escapes
AUTH

Authentication & Access Control

Gebroken authenticatie en autorisatie zijn verantwoordelijk voor een groot deel van alle security breaches.

Kernconcepten

  • JWT Attacks — none algorithm, key confusion (RS256 vs HS256), header injection, JKU/X5U abuse
  • OAuth Abuse — redirect_uri manipulation, scope escalation, CSRF in OAuth flows, token theft
  • SAML XSW — XML Signature Wrapping attacks tegen SAML-gebaseerde SSO
  • IDOR — Insecure Direct Object References. Simpel maar verwoestend: verander een ID, krijg data van een ander
  • Mass Assignment — verborgen parameters toevoegen aan requests om privileged fields te overschrijven
ADV

Advanced Web Attacks

De geavanceerde kwetsbaarheden die het verschil maken tussen een junior en senior pentester.

HTTP Request Smuggling

  • CL.TE en TE.CL desync attacks
  • HTTP/2 downgrade smuggling
  • Request smuggling naar account takeover, cache poisoning, en WAF bypass

Web Cache Poisoning

  • Unkeyed headers en parameters identificeren
  • Cache deception vs cache poisoning
  • Chaining met XSS voor stored-achtige impact via de cache

Prototype Pollution

  • Client-side prototype pollution via __proto__ en constructor.prototype
  • Server-side prototype pollution in Node.js applicaties
  • Gadgets: van prototype pollution naar XSS of RCE

DOM Clobbering

  • HTML elementen die JavaScript globals overschrijven
  • Chaining met andere kwetsbaarheden voor impact

OEFENING 2.2.3 MEDIUM

OEFENING 2.2.4 HARD
HTTP Request Smuggling Payload
Bouw een werkende HTTP request smuggling payload in een lab-omgeving. Demonstreer zowel CL.TE als TE.CL varianten en documenteer de impact.
Toon antwoord

CL.TE payload: POST / HTTP/1.1\r\nHost: target\r\nContent-Length: 13\r\nTransfer-Encoding: chunked\r\n\r\n0\r\n\r\nSMUGGLED. De front-end server gebruikt Content-Length (13 bytes), de back-end gebruikt Transfer-Encoding (0 = end of chunks). Het verschil in parsing laat je een request 'smokkelen' naar de back-end.

OEFENING 2.2.5 HARD
Custom Burp Suite Extension voor IDOR Testing
Schrijf een Burp Suite extension (Python of Java) die automatisch IDOR-kwetsbaarheden test door ID-parameters te detecteren en te manipuleren. De extension moet vergelijkingsresultaten rapporteren.
Toon antwoord

Gebruik Jython/Montoya API. IHttpListener interface, processHttpMessage() method. Filter responses met parameters als 'id', 'user_id', 'account'. Wissel waarden automatisch en vergelijk response length/content. Length-verschil bij andere user's ID = potentiële IDOR.

Essentiële Tools Burp Suite Professional (of Community), ffuf (web fuzzer), nuclei (vulnerability scanner), sqlmap (SQL injection automation), SecLists (wordlists voor alles).

2.3

Netwerk Aanvallen

2-3 WEKEN

Van Layer 2 tot wireless — begrijp hoe netwerken worden aangevallen. ARP spoofing, LLMNR poisoning, relay attacks, pivoting, en draadloze aanvallen.

Diep Begrip: Waarom LLMNR/NBT-NS Poisoning Zo Effectief Is

Wanneer een Windows machine een hostname niet kan resolven via DNS, valt het terug op LLMNR (Link-Local Multicast Name Resolution) en NBT-NS (NetBIOS Name Service). Deze protocollen broadcasten de vraag naar het hele lokale netwerk. Responder antwoordt op deze broadcasts en claimt dat hij de gevraagde host is. De client stuurt vervolgens NTLM authenticatie naar Responder. Dit werkt omdat: 1) LLMNR/NBT-NS zijn standaard ingeschakeld, 2) er geen authenticatie is op de responses, 3) het gebeurt automatisch zonder gebruikersinteractie.

L2

Layer 2 Aanvallen

Het lokale netwerk is vaak minder beveiligd dan mensen denken. Layer 2 aanvallen geven je Man-in-the-Middle positie.

Kernconcepten

  • ARP Spoofing — fake ARP replies om verkeer om te leiden. Basis voor MitM op lokale netwerken
  • DHCP Attacks — rogue DHCP servers, DHCP starvation. Controle over netwerkconfiguratie van clients
  • VLAN Hopping — switch spoofing en double tagging om VLAN-isolatie te doorbreken
NTL

NTLM Poisoning & Relay

In Windows-omgevingen zijn LLMNR, NBT-NS, en NTLM een goudmijn voor aanvallers. Responder en relay attacks zijn essentiële tools.

Kernconcepten

  • LLMNR/NBT-NS Poisoning — Responder vang NTLM hashes op door name resolution te spoofen
  • IPv6 Attacks — mitm6 misbruikt IPv6 autoconfiguratie om verkeer om te leiden
  • SMB Relay — captured NTLM authenticatie doorsturen naar een ander systeem via ntlmrelayx
  • Kerberos Relay — nieuwere relay-technieken die Kerberos-authenticatie misbruiken
PIV

Pivoting & Tunneling

Eén machine gecompromitteerd? Nu moet je dieper het netwerk in. Pivoting is hoe je van foothold naar volledige controle gaat.

Kernconcepten

  • SSH Tunneling — local port forwarding, remote port forwarding, dynamic (SOCKS) proxy
  • Chisel — snelle Go-based tunneling tool voor TCP en SOCKS proxying
  • Ligolo-ng — moderne tunneling tool die volledige netwerktoegang biedt via een TUN interface
WIF

Wireless Attacks

Wi-Fi aanvallen blijven relevant. Van WPA2 handshake captures tot WPA3 Dragonblood en evil twin attacks.

Kernconcepten

  • WPA2 Aanvallen — handshake capture met aircrack-ng, PMKID attack, offline cracking met hashcat
  • WPA3 Dragonblood — side-channel en downgrade attacks op het SAE handshake
  • Evil Twin — nep access point opzetten om credentials te onderscheppen

TLS Attack History

  • BEAST, CRIME, BREACH, POODLE, Heartbleed, DROWN — begrijp de geschiedenis van TLS-kwetsbaarheden en waarom ze werkten

OEFENING 2.3.2 MEDIUM

OEFENING 2.3.3 HARD
NTLM Relay Attack
Stel ntlmrelayx in om captured NTLM-authenticatie door te sturen naar een andere machine in je lab. Demonstreer hoe je zonder het wachtwoord te kraken toegang krijgt tot een systeem.
Toon antwoord

OEFENING 2.3.4 MEDIUM

Capture een WPA2 handshake van je eigen test-netwerk met aircrack-ng suite. Crack het handshake met hashcat en een geschikte wordlist. Documenteer de volledige workflow.
Toon antwoord

Het handshake bevat de 4 EAPOL frames; je crackt niet de key maar het wachtwoord via PBKDF2-SHA1.

2.4

Binary Exploitation Intro

2-3 WEKEN

Stap naar het laagste niveau. Begrijp hoe programma's in het geheugen leven, hoe de stack werkt, en hoe je met een zorgvuldig gecrafted input een programma kunt overnemen.

Diep Begrip: Waarom Buffer Overflows Nog Steeds Bestaan

Waarom buffer overflows nog steeds bestaan ondanks decennia van mitigaties — Elke mitigatie heeft een bypass. ASLR randomiseert adressen maar information leaks onthullen de base address. NX/DEP voorkomt code execution op de stack maar Return-Oriented Programming (ROP) hergebruikt bestaande code. Stack canaries detecteren overwrites maar format string bugs kunnen ze lezen. Het is een arms race. Moderne exploits chainen meerdere bugs: een info leak (bypass ASLR) + een write primitive (bypass canary) + ROP chain (bypass NX). Dit is waarom 'defence in depth' werkt — elke laag maakt exploitatie exponentieel moeilijker.

ASM

x86_64 Assembly & Memory Layout

Je kunt geen binaries exploiteren als je niet begrijpt hoe ze werken. Assembly lezen is een vereiste.

Kernconcepten

  • x86_64 Assembly — registers (RAX, RBX, RSP, RBP, RIP), instructies (MOV, PUSH, POP, CALL, RET, JMP), en hoe je disassembly leest
  • Calling Conventions — System V AMD64 ABI: parameters in RDI, RSI, RDX, RCX, R8, R9. Return value in RAX
  • Stack Layout — hoe de stack groeit (hoog naar laag), stack frames, local variables, saved RBP, return address
BOF

Buffer Overflow & Exploitation

De klassieke kwetsbaarheid. Overschrijf het return address op de stack en neem de controle over de executie over.

Kernconcepten

  • Classic Buffer Overflow — stack-based buffer overflow, return address overschrijven, shellcode injecteren
  • Format String Bugs — %x lekken van stack data, %n schrijven naar willekeurige adressen
  • Heap Basics — malloc/free internals, use-after-free, double free — introductie (diepgang in Fase 4)

Mitigaties & Bypasses

  • ASLR — Address Space Layout Randomization. Brute force, info leaks, partial overwrites
  • NX/DEP — No-Execute bit. De stack is niet meer uitvoerbaar — dus gebruiken we ROP
  • ROP (Return-Oriented Programming) — chains van bestaande code-gadgets om willekeurige operaties uit te voeren
  • Stack Canaries — detectie van stack overwrites. Bypasses via info leaks of brute force
  • CFI — Control Flow Integrity. Modernere bescherming tegen controle-flow hijacking

Toon antwoord

Program Interaction leert je hoe processen communiceren (stdin/stdout/pipes/files). Assembly leert je x86_64 instructies. Cruciale registers: RIP (instruction pointer), RSP (stack pointer), RBP (base pointer), RAX (return value). De stack groeit naar lagere adressen; een buffer overflow overschrijft de saved RBP en return address boven de buffer.

OEFENING 2.4.2 HARD
Classic Stack Buffer Overflow Exploit
Schrijf een complete stack buffer overflow exploit from scratch. Bepaal de offset naar het return address, genereer shellcode (of gebruik een bestaande), en redirect de executie. Gebruik GDB en pwntools.
Toon antwoord

Vulnerable code: char buf[64]; gets(buf); Exploit: 1) Vind offset naar return address (pattern create + offset), 2) Vind bruikbaar gadget of functie (bijv. system()), 3) Bouw payload: padding + saved RBP + return address. Met NX uitgeschakeld: padding + shellcode address. Met NX aan: ROP chain naar system('/bin/sh').

OEFENING 2.4.3 HARD
ROP Emporium — ret2win
Voltooi de ret2win challenge op ROP Emporium. Bouw een ROP chain die een bestaande functie aanroept door het return address te overschrijven. Begrijp waarom dit werkt ondanks NX.
Bron: ROP Emporium (ropemporium.com)
Toon antwoord

De uitdaging geeft een binary met een 'ret2win' functie die nooit aangeroepen wordt. Overflow de buffer, overschrijf return address met het adres van ret2win(). Op x86_64: let op stack alignment (16-byte aligned vóór CALL). Voeg een 'ret' gadget toe voor alignment als je een segfault krijgt.

OEFENING 2.4.4 HARD

Exploiteer een format string kwetsbaarheid in een practice binary. Gebruik %x om stack data te lekken en %n om naar een specifiek adres te schrijven. Documenteer elke stap.
Toon antwoord

2.5

Active Directory — Op Aanvaller-Niveau

3-4 WEKEN

Active Directory draait in 95% van Fortune 500 bedrijven. Het is het primaire doelwit in enterprise-omgevingen. Leer het van binnenuit aanvallen — van enumeratie tot Domain Admin.

Diep Begrip: Waarom Kerberos Zo Complex en Kwetsbaar Is

Kerberos is ontworpen in de jaren '80 voor een ander dreigingsmodel. De fundamentele aanname was: als je de encryption key kent, ben je geautoriseerd. AS-REQ: client bewijst identiteit met password hash → krijgt TGT (versleuteld met krbtgt hash). TGS-REQ: client toont TGT → krijgt service ticket (versleuteld met service account hash). Het probleem: als je de krbtgt hash hebt, kun je ELKE TGT maken (Golden Ticket). Als je een service account hash hebt, kun je een geldig service ticket maken (Silver Ticket). Kerberoasting werkt omdat je een service ticket kunt AANVRAGEN voor elke SPN en offline de hash kunt kraken — de server geeft het ticket gewoon.

AD

AD Structuur & Protocollen

Voordat je AD kunt aanvallen, moet je het diep begrijpen. Hoe Kerberos werkt, hoe NTLM faalt, en waar de misconfigurations zitten.

Kernconcepten

  • AD Structure — forests, domains, OUs, trusts, domain controllers, global catalog
  • Kerberos in Detail — AS-REQ/AS-REP, TGS-REQ/TGS-REP, TGT, service tickets, PAC, delegation (constrained, unconstrained, resource-based)
  • NTLM Authentication — challenge-response, Net-NTLMv1/v2 hashes, relay aanvallen
  • GPO Abuse — Group Policy Objects misbruiken voor privilege escalation en lateral movement
  • LDAP Queries — handmatige en geautomatiseerde AD-enumeratie via LDAP

2.6

Cloud Attack Surface

2-3 WEKEN

De perimeter is verplaatst naar de cloud. Misconfigured S3 buckets, overprivileged IAM roles, en metadata service SSRF zijn de nieuwe low-hanging fruit.

Diep Begrip: Waarom IMDSv1 SSRF de 'Heilige Graal' Is

AWS metadata service (169.254.169.254) is bereikbaar vanaf elke EC2 instance. IMDSv1 accepteert simpele GET requests. Als je een SSRF hebt in een webapplicatie op EC2, kun je http://169.254.169.254/latest/meta-data/iam/security-credentials/ROLE_NAME opvragen en tijdelijke AWS credentials krijgen. Met die credentials kun je alles doen waar de IAM role rechten voor heeft. IMDSv2 vereist een PUT request met een hop-limit header, wat de meeste SSRF's blokkeert. Maar veel organisaties hebben IMDSv1 nog niet uitgeschakeld.

Cloud IAM & Misconfigurations

Identity and Access Management is de ruggengraat van cloud security. En het is bijna altijd verkeerd geconfigureerd.

Kernconcepten

  • Misconfigured S3 Buckets — publieke buckets, directory listing, unauthenticated uploads — nog steeds een van de meest voorkomende fouten
  • Metadata Service SSRF (IMDSv1) — 169.254.169.254 endpoint misbruiken om IAM credentials te stelen van EC2 instances
  • Cross-Account Attacks — IAM role assumption, resource policies, en trust relationships tussen accounts misbruiken

Ethiek is niet optioneel.

  • In Nederland: lees de Leidraad Responsible Disclosure van het NCSC
