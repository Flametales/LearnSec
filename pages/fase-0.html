MOD 0.1

Netwerk Self-Audit.

1-2 WEKEN · KERNMODULE

TCP/IP, DNS, subnetting, het OSI-model — de fundamenten waarop alles in cybersecurity is gebouwd. Als je niet kunt uitleggen wat er op de draad gebeurt, ben je blind.

0.1

Netwerken: van packet tot applicatie

Dit gaat niet over theorie memoriseren. Je moet een packet trace kunnen lezen, subnets kunnen berekenen, en weten hoe DNS resolution echt werkt — recursief, iteratief, caching, het hele verhaal.

Diep Begrip: TCP Sequence & Acknowledgment Nummers

Waarom TCP zowel sequence- als acknowledgment-nummers heeft — De asymmetrie is belangrijk. TCP is full-duplex: elke richting heeft zijn eigen stream met eigen sequence nummers. Het acknowledgment nummer vertelt de afzender hoeveel van zijn data succesvol ontvangen is. Dit maakt het mogelijk om data in beide richtingen tegelijk te verzenden en te bevestigen. Een veelgemaakte fout is denken dat ACK-nummers de eigen sequentie bevestigen — ze bevestigen de ANDERE kant.

Kernconcepten

  • TCP/IP Stack — Begrijp elk layer: link, internet, transport, applicatie. Weet welke protocollen waar leven.
  • TCP Three-Way Handshake — SYN, SYN-ACK, ACK met sequence numbers. Weet waarom dit bestaat en wat er misgaat zonder.
  • UDP vs TCP — Wanneer connectionless zinvol is. DNS over UDP vs TCP. Streaming vs reliability.
  • DNS Resolution — Stub resolver → recursive resolver → root → TLD → authoritative. Caching, TTL, NXDOMAIN.
  • Subnetting — CIDR-notatie, netmaskers, broadcast adressen, beschikbare hosts berekenen. Moet je op papier kunnen.
  • ARP & MAC Addressing — Layer 2 resolution. ARP tables, gratuitous ARP, en waarom ARP spoofing werkt.
  • Wireshark Basics — Capture filters vs display filters. TCP stream volgen. HTTP requests herkennen.

Oefeningen

OEFENING 0.1.1
MEDIUM
TCP Three-Way Handshake tekenen
Teken de volledige TCP three-way handshake op papier of in een diagramtool. Geef bij elke stap de exacte TCP flags aan (SYN, SYN+ACK, ACK) en de bijbehorende sequence en acknowledgment numbers. Beschrijf wat er gebeurt als het derde pakket (ACK) verloren gaat.
Bron: Practical Networking · TCP Fundamentals
Toon antwoord

SYN (seq=x) → SYN-ACK (seq=y, ack=x+1) → ACK (seq=x+1, ack=y+1). De SYN flag consumeert één sequence nummer. Na de handshake begint data-overdracht. Het cruciale inzicht: de ACK-waarde is altijd het VOLGENDE byte dat de ontvanger verwacht.

OEFENING 0.1.2
HARD
DNS query tracen voor mail.google.com
Beschrijf stap voor stap de volledige DNS resolution chain voor mail.google.com. Begin bij de stub resolver op je OS, ga via de recursive resolver naar de root servers, dan de .com TLD, dan de google.com authoritative nameserver. Geef bij elke stap aan welk type query (A, AAAA, CNAME, MX) wordt gestuurd. Gebruik dig +trace mail.google.com om je antwoord te verifiëren.
Bron: PowerCert DNS · RFC 1035
Toon antwoord

Client → Local resolver (recursief) → Root servers (.com NS) → TLD servers (google.com NS) → Authoritative server (mail.google.com A record). EDNS(0) voegt buffer size en DNSSEC flags toe. DNSSEC valideert via een chain of trust: root KSK → root ZSK → .com DS → .com KSK → etc.

OEFENING 0.1.3
MEDIUM
Subnet 10.0.0.0/22 verdelen
Verdeel het netwerk 10.0.0.0/22 in vier gelijke subnets. Geef voor elk subnet het netwerkadres, het broadcast adres, het bereik van bruikbare IP-adressen, en het subnetmasker in zowel CIDR als decimale notatie. Hoeveel hosts passen er in elk subnet?
Bron: Professor Messer · Seven Second Subnetting
Toon antwoord

10.0.0.0/22 = 10.0.0.0 - 10.0.3.255 (1024 adressen). Vier /24 subnetten: 10.0.0.0/24 (broadcast: 10.0.0.255), 10.0.1.0/24 (broadcast: 10.0.1.255), 10.0.2.0/24 (broadcast: 10.0.2.255), 10.0.3.0/24 (broadcast: 10.0.3.255).

OEFENING 0.1.4
HARD
HTTP-verkeer capturen met Wireshark
Open Wireshark en capture verkeer terwijl je een HTTP-website bezoekt (geen HTTPS). Identificeer de volledige TCP handshake in de capture. Filter op de juiste poort. Volg de TCP stream en bekijk de HTTP GET request en het response. Maak een screenshot van de handshake en annoteer de sequence numbers.
Bron: Wireshark Documentation · Chris Greer's Packet Analysis
Toon antwoord

Filter: tcp.flags.syn==1. Je ziet drie pakketten: SYN, SYN-ACK, ACK. Noteer de sequence nummers en bevestig dat ze het patroon volgen. Zoek ook naar TCP retransmissions en window size negotiation.

MOD 0.2

Linux Internals.

1-2 WEKEN · KERNMODULE

Linux is het slagveld. Servers, containers, IoT — als je de kernel, het filesystem, en processen niet begrijpt, ben je verloren als pentester én als defender.

0.2

Van kernel tot userspace

Dit gaat verder dan ls en cd. Je moet begrijpen hoe processen werken, wat /proc onthult, hoe permissions en capabilities echt functioneren, en hoe Linux security primitieven (namespaces, cgroups, capabilities) de basis vormen van moderne containerisatie.

Diep Begrip: fork() en execve() als twee aparte operaties

fork() en execve() zijn twee aparte operaties met een reden — fork() kopieert het huidige proces (copy-on-write in werkelijkheid), execve() vervangt de huidige process image met een nieuw programma. Deze scheiding geeft de parent de kans om het kind-proces te configureren (file descriptors omleiden, environment instellen) vóórdat het nieuwe programma start. Dit is hoe pipes en I/O redirection in de shell werken. Het alternatief — één syscall die alles doet — zou veel minder flexibel zijn.

Kernconcepten

  • Filesystem Hierarchy — /proc, /sys, /dev, /etc, /var/log. Weet wat elk bevat en waarom.
  • Processen & PID — fork(), execve(), zombie processen, orphans. De process tree van init/systemd tot je shell.
  • /proc filesystem — /proc/self/maps, /proc/[pid]/fd, /proc/[pid]/status. Runtime informatie van elke process.
  • File Descriptors — stdin(0), stdout(1), stderr(2). Hoe alles in Linux een bestand is. Sockets, pipes, device files.
  • Permissions & Capabilities — rwx, setuid, setgid, sticky bit. Linux capabilities als fijnmaziger alternatief voor root.
  • Namespaces & Cgroups — De bouwstenen van containers. PID namespace, network namespace, mount namespace. Cgroups voor resource limiting.
  • Systemd & Services — Unit files, journalctl, service management. Hoe moderne Linux systemen opstarten en diensten beheren.

Oefeningen

OEFENING 0.2.1
MEDIUM
/proc/self/maps lezen en uitleggen
Open een terminal en voer cat /proc/self/maps uit. Leg voor elke regel uit wat je ziet: het adresbereik, de permissions (r/w/x/p), de offset, het device, de inode, en de mapping (stack, heap, shared library, of het binary zelf). Identificeer waar libc geladen is en waar de stack zich bevindt.
Bron: Linux Kernel Documentation · proc(5) man page
Toon antwoord

Elke regel toont: adresbereik, permissions (rwxp), offset, device, inode, pathname. Zoek naar: [stack] (de stack), [heap] (de heap), libc.so (gedeelde bibliotheken), [vdso] (kernel syscall optimization). De permissions vertellen je welke memory regions executable zijn — een verdacht executable heap segment kan wijzen op shellcode.

OEFENING 0.2.2
MEDIUM
Open file descriptors onderzoeken met lsof
Start een langlopend proces (bijv. python3 -m http.server 8080). Gebruik lsof -p [PID] om alle open file descriptors te bekijken. Identificeer stdin, stdout, stderr, de socket, en eventuele geopende bestanden. Verklaar elk type (REG, DIR, IPv4, sock). Probeer ook ls -la /proc/[PID]/fd/ en vergelijk.
Bron: lsof(8) man page · Linux kernel /proc filesystem
Toon antwoord

lsof -p <PID> toont alle open file descriptors. FD 0=stdin, 1=stdout, 2=stderr. TYPE=IPv4/IPv6 wijst op netwerk-sockets. cwd=current working directory. Door lsof te combineren met netstat/ss zie je welke processen welke netwerkverbindingen hebben.

OEFENING 0.2.3
HARD
Simpele container bouwen met namespaces en cgroups
Maak handmatig een geïsoleerde omgeving zonder Docker. Gebruik unshare om een nieuw PID en mount namespace te creëren. Mount een minimaal root filesystem (bijv. Alpine minirootfs). Gebruik cgroups v2 om het geheugengebruik te beperken. Verifieer isolatie: controleer dat ps in de container alleen de eigen processen toont. Documenteer elke stap.
Bron: "Containers from Scratch" · Liz Rice (GOTO Conference)
Toon antwoord

unshare --mount --uts --ipc --net --pid --fork /bin/bash creëert een nieuw proces met eigen namespaces. Je bent nu 'root' in de PID namespace maar niet op het hostsysteem. cgroups limiteren resources: echo $PID > /sys/fs/cgroup/memory/container1/cgroup.procs beperkt geheugengebruik.

OEFENING 0.2.4
HARD
Setuid vs capabilities vergelijken
Creëer een simpel C-programma dat een raw socket opent (vereist CAP_NET_RAW). Compileer het en probeer het als normale gebruiker. Maak het vervolgens setuid root — merk op dat het werkt maar gevaarlijk is. Verwijder setuid en ken alleen CAP_NET_RAW toe met setcap. Vergelijk de security-implicaties van beide aanpakken. Gebruik getcap en getfattr om te verifiëren.
Bron: capabilities(7) man page · Linux Security Modules
Toon antwoord

setuid geeft ALLE privileges van de file owner (meestal root). Capabilities splitsen root-privileges in granulaire eenheden: CAP_NET_RAW voor raw sockets, CAP_DAC_OVERRIDE voor file access. setcap cap_net_raw+ep /usr/bin/ping is veiliger dan chmod u+s /usr/bin/ping omdat het alleen netwerk-privileges geeft.

  • Ik kan uitleggen waarom capabilities beter zijn dan setuid root
  • Ik ken de Linux filesystem hierarchy en weet wat /proc, /sys, en /dev bevatten
  • Ik begrijp hoe fork() en execve() werken om nieuwe processen te starten

Programmeer-Polish.

1-2 WEKEN · KERNMODULE

Je hoeft geen software engineer te zijn, maar je moet code kunnen lezen, schrijven, en debuggen. Python voor tooling, C voor exploits begrijpen, Git voor alles.

0.3

Code als wapen & schild

In cybersecurity schrijf je scripts, lees je exploits, en automatiseer je taken. Python is je dagelijkse tool. C begrijpen is noodzakelijk voor binary exploitation. Git is hoe de security-community werkt.

Diep Begrip: Waarom Python en C beide essentieel zijn voor security

Waarom Python en C beide essentieel zijn voor security — Python is je automation taal: snel prototypen, scripting, tool-building. C is je 'begrijp-de-machine' taal: memory layout, pointers, buffer overflows zijn onmogelijk te begrijpen zonder C te lezen. Je hoeft niet goed in C te schrijven — je moet het vloeiend kunnen LEZEN, omdat de meeste exploits, kernels, en security-critical code in C geschreven is.

Kernconcepten

  • Python Fundamentals — Data types, functies, classes, file I/O, error handling. Genoeg om een tool te bouwen.
  • Python Networking — De socket module. TCP/UDP clients en servers bouwen. HTTP requests met requests.
  • C Lezen — Pointers, memory allocation, structs, system calls. Je hoeft niet in C te schrijven, maar je moet het kunnen lezen.
  • Process Creation in C — fork(), execve(), wait(). Hoe Unix processen echt werken onder de motorkap.
  • Git Workflow — clone, branch, commit, merge, rebase. Pull requests. git bisect om bugs te vinden. git log lezen.
  • Scripting Mindset — Automatiseer repetitieve taken. Als je iets drie keer handmatig doet, schrijf een script.

Oefeningen

OEFENING 0.3.1
MEDIUM
Port scanner bouwen in Python
Bouw een simpele port scanner met de Python socket module. Het script moet een target IP en een range van poorten accepteren als argumenten. Gebruik socket.connect_ex() voor elke poort en print welke open zijn. Voeg een timeout toe van 1 seconde per poort. Bonus: maak het multithreaded met concurrent.futures.ThreadPoolExecutor en vergelijk de snelheid. Test alleen op je eigen machines of scanme.nmap.org.
Bron: Black Hat Python · Python socket module docs
Toon antwoord

import socket; for port in range(1, 1025): s = socket.socket(); s.settimeout(0.5); result = s.connect_ex(('target', port)); if result == 0: print(f'Port {port} open'); s.close(). Verbeterde versie: gebruik concurrent.futures.ThreadPoolExecutor voor snelheid, en voeg banner grabbing toe met s.recv(1024).

OEFENING 0.3.2
HARD
C-programma met fork() en execve() lezen en uitleggen
Bekijk het volgende C-patroon: een programma dat fork() aanroept, in het child process execve("/bin/ls", args, envp) uitvoert, en in het parent process waitpid() aanroept. Teken de process tree die ontstaat. Beantwoord: wat is het verschil tussen fork() en exec()? Waarom returnt fork() twee keer? Wat gebeurt er als je waitpid() weglaat? Schrijf het programma na en voer het uit.
Bron: Advanced Programming in the UNIX Environment · Stevens & Rago
Toon antwoord

fork() returnt 0 in het child, PID van child in parent, -1 bij fout. Na fork delen parent en child dezelfde file descriptors (copy-on-write memory). execve() vervangt het child's memory image volledig — code, data, stack worden vervangen door het nieuwe programma.

OEFENING 0.3.3
MEDIUM
Git bisect gebruiken om een bug te vinden
Clone een repository met een bekende bug ergens in de history (maak er zelf een aan met 10+ commits als je geen goede vindt). Gebruik git bisect start, markeer een goede en slechte commit, en laat Git binary search doen om de exacte commit te vinden die de bug introduceerde. Documenteer het volledige proces: welke commits heb je getest, hoe heeft bisect je geleid, en welke commit was de boosdoener?
Bron: Pro Git Book · git-bisect(1) man page
Toon antwoord

git bisect start; git bisect bad (huidige commit is broken); git bisect good <known-good-commit>; Git kiest automatisch een commit halverwege. Test, markeer good/bad, herhaal. Logaritmische complexiteit: 1000 commits vereist ~10 tests.

Ethische richtlijn voor Fase 0

De tools en technieken die je hier leert — port scanning, packet capturing, process inspection — zijn dual-use. Dezelfde kennis die een pentester gebruikt om kwetsbaarheden te vinden, kan een crimineel gebruiken om schade aan te richten.

Het verschil is autorisatie. Altijd.

  • Scan alleen je eigen netwerken en machines, of gebruik expliciet toegestane doelen zoals scanme.nmap.org
  • Capture alleen verkeer op netwerken waar je toestemming voor hebt
  • Gebruik je kennis om te beschermen, niet om te breken
  • Als je twijfelt of iets mag: het mag niet. Vraag eerst toestemming.
  • Lees de wetgeving: in Nederland valt ongeautoriseerde toegang onder Art. 138ab Wetboek van Strafrecht (computervredebreuk)
